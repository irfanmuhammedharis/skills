# Review Checklists

Reviews find what DRC cannot: intent errors. Run each checklist as a separate pass, with evidence
recorded, not as a mental skim. Answer each item with a fact ("measured 0.62 mm", "see calc in
design record §4"), never with "yes".

## Contents
1. How to run a review
2. Schematic sign-off
3. Placement sign-off
4. Layout sign-off
5. Pre-release (fab) gate
6. Bring-up preparation

## 1. How to Run a Review

- Review against the *requirement*, not against the drawing: for each requirement in the design
  record, point at the part of the design that satisfies it.
- Print or export PDFs; reviewing on the schematic editor screen hides half the sheet.
- Two passes with different mindsets: **"does it match intent"** (nets, values, pinouts) and
  **"how will it fail"** (worst-case, transients, thermal, assembly, field).
- A second pair of eyes on pinouts and connectors is worth more than any tool. If nobody else is
  available, review the next day, not the same hour.
- Track every finding to closure with a decision: fixed / accepted with reason / deferred to
  next revision.

## 2. Schematic Sign-Off

- [ ] Every requirement in the design record maps to circuitry
- [ ] Power tree complete: every rail's worst-case current computed, converter derated ≥1.3×
- [ ] Sequencing and enable logic correct; no back-powering path through I/O or protection diodes
- [ ] Every IC checked against its datasheet application section (externals, values, reset,
      boot/strapping, unused-pin handling)
- [ ] MCU pin assignment verified against the alternate-function table, including boot straps,
      ADC-capable pins, and pins in use during programming
- [ ] Pull-ups/downs present where a bus or a strap requires them, values computed
- [ ] Decoupling per power pin present in the schematic (it cannot appear in layout if it is not
      here)
- [ ] Connector pinouts checked against the mating part datasheet — pin 1 orientation, gender,
      and any crossover (TX/RX, differential polarity)
- [ ] Protection on every external interface: ESD, reverse polarity, overvoltage, inrush
- [ ] Test points on all rails and bring-up-critical signals
- [ ] Component ratings: voltage (with DC bias derating on MLCCs), power, current, temperature
- [ ] Footprint assigned to every symbol and verified as the correct package variant
- [ ] BOM fields complete: MPN, manufacturer, supplier PN, tolerance/voltage where it matters
- [ ] Parts in stock in the required quantity; second sources identified for critical parts
- [ ] DNP / exclude-from-BOM / exclude-from-board set intentionally
- [ ] ERC clean; every exclusion has a written reason
- [ ] Net names and refdes are meaningful; sheet titles and revision filled in

## 3. Placement Sign-Off

- [ ] Mechanical parts match the drawing (measured in the 3D or board view)
- [ ] 3D check against enclosure STEP: no collisions, height clearances met
- [ ] Hot loops, decoupling, crystal, RF cluster tight (placement.md §2–3)
- [ ] Thermal sources spread and away from sensors, electrolytics, and batteries
- [ ] Courtyards non-overlapping; assembly and rework access acceptable
- [ ] Polarised parts consistently oriented per region
- [ ] Test points, fiducials, mounting holes, and keep-outs placed
- [ ] Ratsnest untangled; layer plan can carry the remaining connections

## 4. Layout Sign-Off

- [ ] Netclass widths and clearances applied everywhere; no default-class stragglers on power
- [ ] Every calculated width used (current, impedance) — spot-check three nets against the calcs
- [ ] No signal crosses a plane split or void; return vias at every layer change on fast nets
- [ ] Differential pairs coupled, uncoupled budget respected, skew inside spec
- [ ] Length/delay-matched groups tuned and constrained by rule
- [ ] Antenna keep-out clear on all layers; RF feed matches the vendor reference
- [ ] Power polygons continuous and stitched; no thin necks (check `connection_width`)
- [ ] Thermal vias present and connected to real copper on the far side
- [ ] Zones refilled; no isolated islands; min width above fab floor
- [ ] Copper-to-edge clearance respected; board outline single closed loop
- [ ] Silkscreen: no text over pads/vias, ≥1 mm height, pin-1 and polarity marks, connector
      labels, board name + revision + date
- [ ] Mask/paste correct: no unintended overrides, thermal pad paste windowpaned
- [ ] High-voltage separation and creepage verified by rule, not by eye
- [ ] DRC clean with schematic parity, all severities reviewed, exclusions justified in writing
- [ ] 3D render inspected top and bottom at high zoom

## 5. Pre-Release (Fab) Gate

- [ ] ERC + DRC reports generated by CLI and stored with the package
- [ ] `audit_project.py` run and findings resolved
- [ ] Gerbers re-imported into GerbView and inspected layer by layer, including drill overlay
- [ ] Drill table sane; PTH/NPTH split correct; no zero-size holes
- [ ] BOM and CPL checked (counts, coordinates, rotations, DNP handling)
- [ ] STEP export opens and matches the enclosure model
- [ ] Fab notes written: stackup, finish, impedance, tenting, slots, IPC class, marking
- [ ] Panel requirements agreed with the assembler if panelized
- [ ] Cost and lead time confirmed against the budget in the design record
- [ ] Everything committed and tagged; the package is reproducible from the tag by one command

## 6. Bring-Up Preparation

Prepare *before* the boards arrive; a rushed first power-on destroys prototypes.

- [ ] Bring-up procedure written: current-limited supply first, expected current at each step,
      rail-by-rail measurement order, go/no-go criteria
- [ ] Known-good measurement points listed with expected values (from the design calcs)
- [ ] Programming/debug path tested conceptually: connector pinout, voltage levels, boot mode
- [ ] Assembly aids ready: interactive HTML BOM, assembly drawing, paste stencil ordered
- [ ] A "what could be wrong" list from the review's failure-mode pass, with the check for each
- [ ] Measurement plan for the numbers you promised: thermal rise, rail ripple, current draw,
      RF output — record them in the design record so revision B starts from data
